## URGENT: Fix needed — MartinLoop not working in Claude Code desktop or Codex IDE, only PowerShell

### What the user reported
"it's not working on claude code or codex, it's only working on powershell"

### Root cause hypothesis
The engineer's Windows shim fix (`createSpawnPlan` in `packages/adapters/src/cli-bridge.ts`) resolves npm shims to their real `node <script>.js` target. This removes the extra `cmd.exe` hop. However:

1. **Claude Code desktop** spawns subprocesses with its own sandboxed environment. The `--strict-mcp-config` flag we added prevents MCP server conflicts, but Claude Code's extension host may be setting additional environment restrictions that `node <script>.js` invocation doesn't inherit correctly.

2. **Codex app/IDE** (not Codex CLI) — unclear if this is the OpenAI Codex CLI or the VS Code extension. If VS Code Codex extension, it has different subprocess permissions than terminal PowerShell.

3. **The shim fix** only applies when `process.platform === 'win32'` AND the command resolves to a `.cmd/.bat/.ps1` file AND `resolveNpmShimScript` succeeds. If any of these fail, it falls back to `cmd.exe` wrapping — which is the problem.

### Files to investigate
- `packages/adapters/src/cli-bridge.ts` — `createSpawnPlan` + `resolveNpmShimScript`
- `packages/adapters/src/claude-cli.ts` — `createClaudeCliAdapter` args (`--strict-mcp-config`, `--dangerously-skip-permissions`)
- `packages/adapters/src/codex-launcher.ts` — `buildCodexExecArgs`, shim resolution for Codex probe

### Specific things to check
1. Does `resolveNpmShimScript` actually find the real script for `claude.cmd`? Add diagnostic logging.
2. When spawned inside Claude Code desktop, does `process.execPath` point to the right Node? Claude Code bundles its own Node.
3. For Codex: does `codex exec --sandbox workspace-write` work from inside VS Code terminal vs PowerShell?
4. Is `CLAUDE_CODE=1` set when running inside Claude Code desktop? Use this to detect and adjust spawn behavior.

### Likely fix direction
The shim resolution may be failing silently (returning `undefined`) for Claude Code's bundled Node or for Codex's specific shim format. When it fails, the code falls back to `cmd.exe` wrapping — which is the broken path inside IDE environments.

Fix: make `resolveNpmShimScript` more robust, and add IDE-context detection to choose the right spawn strategy.
