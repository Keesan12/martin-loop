**Period:** 2026-08-21 through 2026-08-29
**Owner repo:** `private OSS staging repository`
**Purpose:** preserve factual evidence from the 0.5.5 -> 0.5.6 -> 0.5.7 release train so the same product, packaging, harness, and process failures are not rediscovered in future releases.

## CORE-055-001 — execution knobs contaminated governance scope identity

```text
BUG_ID=CORE-055-001
SURFACE=CLI workflow-state / preflight -> run gate
SEVERITY=P1
CATEGORY=PRODUCT
FIRST_OBSERVED=public-package hardening before/around 0.5.5
AFFECTED_RELEASES=pre-0.5.5 lineage; fixed in later Core
SOURCE_REPO=private OSS staging repository
LIKELY_OWNER=CLI governance state / receipt-scope logic
STATUS=RESOLVED
```

**REPRO_STEPS:** Run `doctor -> estimate -> session-start -> preflight`, then invoke `run` with `--budget-usd` / `--max-iterations` that were not part of the prior scope identity.
**EXPECTED:** Valid preflight for the same repo/objective/verifier/path scope remains valid.
**ACTUAL:** `run` returned `policy_blocked` / "preflight missing" even though workflow-state contained a valid preflight receipt.
**ROOT_CAUSE:** execution knobs such as budget and max-iterations participated in the governance scope key, so the gate treated execution-policy changes as if repository safety scope had changed.
**USER_IMPACT:** first real governed run could loop forever between successful preflight and `policy_blocked`.
**EVIDENCE:** public defect report showed preflight `scopeKey`, `budgetKey`, and verification key present while `run` recomputed a different key after adding execution knobs; reproduced twice in isolated `--runs-dir` roots.
**CORRECTIVE_ACTION:** separate safety-binding scope identity from execution knobs and make estimate/budget freshness explicit rather than overloading scope identity.
**REGRESSION_PROOF:** objective/scope/verifier changes still invalidate as intended; budget changes invalidate estimate rather than masquerading as repository-scope drift.
**PREVENTIVE_CONTROL:** every workflow-state key must document which invariant it binds; no execution knob may silently enter a repository/safety identity hash.

## CORE-055-002 — global workflow-state caused cross-repository contamination

```text

SURFACE=CLI governance persistence
SEVERITY=P1
CATEGORY=PRODUCT

AFFECTED_RELEASES=pre-0.5.5 lineage; fixed in later Core
SOURCE_REPO=private OSS staging repository
LIKELY_OWNER=workflow-state persistence
STATUS=RESOLVED
```

**REPRO_STEPS:** Run governance sequences concurrently in Repo A and Repo B using the default global runs root; return to Repo A and invoke `run`.
**EXPECTED:** Repo B cannot invalidate Repo A's prerequisite state.
**ACTUAL:** the single global `_martin/workflow-state.json` was last-write-wins; Repo B overwrote Repo A's state and Repo A reported "preflight missing."
**ROOT_CAUSE:** mutable prerequisite state was global rather than workspace/runs-root scoped.
**USER_IMPACT:** parallel terminals, CI jobs sharing a home directory, or MCP + CLI use could invalidate each other.
**EVIDENCE:** reproduced with two repositories; the default state file stored one entry per step type rather than per workspace.
**CORRECTIVE_ACTION:** scope workflow state to repository/workspace identity and runs root.
**REGRESSION_PROOF:** separate workspaces retain independent prerequisite receipts.
**PREVENTIVE_CONTROL:** concurrency/isolation tests are mandatory for any mutable governance state.

# Systemic lessons to train on

1. **Artifact truth beats workspace truth.** Unit/integration green is necessary but insufficient; pack, install, registry-normalized metadata, and protocol schemas need direct proof.
2. **Separate authorities.** Scope authorization, provenance/grounding, semantic indexing, runtime selection, policy, budget, verification, and final decision are distinct authorities. Bugs appeared when one was used as a proxy for another.
3. **The product owns its state machine.** Mandatory prerequisite choreography belongs inside `martin run`, not in README instructions or agent memory.
4. **Absence has semantics.** Optional limits must remain absent; do not encode "unbounded" with arbitrary sentinels.
5. **Public is an output.** Promote only reviewed public-safe deltas from exact Internal authority; Internal absence does not authorize public deletion.
6. **Close the release train.** After immutable merge/tag/publish proof, stop source churn. New improvements belong to the next train.
7. **Harness failures are not product failures, but they still need durable incident evidence.** Deterministic tests must control PATH/provider provenance, TTY state, canonical paths, and generated dependency residue.
8. **Never claim what did not execute.** Zero-step hosted CI remains `BLOCKED_ZERO_STEP_RUNNER_ADMISSION_NOT_CLAIMED_PASS`; it is not an incident and not PASS.
